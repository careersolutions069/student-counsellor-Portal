# Student portal and private documents implementation plan

Goal — Complete read-only student progress, four-channel login sharing, and Centre Head controlled document submission.
Architecture — Reuse signed student cookies and the service-only student_portal projection. Staff checklist writes use their authenticated RLS connection. Uploads use a server action, immutable random Storage paths and a service-only finalization RPC that rechecks the active actor/session, branch, document version and student upload permission under database locks. Private bucket has no client policies. File viewing validates the current actor and returns a 60-second signed URL. Replaced files are removed only after the new metadata commits; failed finalization removes the staged upload.
