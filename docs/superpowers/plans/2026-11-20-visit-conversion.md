# Visit conversion and random registration implementation plan

Goal — Save Centre Head visit details and a private college PDF first, then separately generate an audited random registration ID after DOB entry.
Architecture — Keep students as the source of truth. Revoke direct authenticated access to fee/PDF columns and writes to visit completion metadata. A manager-only, branch-scoped SETOF students RPC supplies Owner/Centre Head records; an invoker view lists only safe caller columns. Visit saves use the authenticated manager connection and a PostgreSQL function that locks the student, checks branch/current PDF snapshot, validates required values and commits the new file reference with audit triggers. Server uploads use immutable branch/student/college-registration UUID.pdf paths in the existing private bucket. File viewing rechecks current manager/branch access and issues a 60-second URL. The two registration forms remain separate.
