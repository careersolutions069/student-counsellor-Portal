# Bulk lead import and owner conversion reports

Goal — Add validated CSV/XLS/XLSX imports and owner-only branch, caller and phase reporting within the existing dashboards.
Architecture — Share parsing/validation between a lazy import panel and its server action. Pass all parsed rows to a guarded authenticated database RPC which validates again, skips globally unique phone conflicts atomically, assigns accepted rows only, and writes a summary audit. Owner reports aggregate in one role-checked SQL RPC; the page and CSV export use the same filter/parser and aggregation. Existing per-student audit triggers remain intact.

Reporting definitions — Dates are inclusive IST calendar dates over students.created_at (lead cohort); all related outcomes are current lifetime outcomes for those leads. All Time has no date bounds. This Month starts on IST month start; Last 7/30 Days include today and the prior 6/29 days. Active branches only. Branch counts use unique students, including cancelled/missed historical invitations. Visits include completed visit details OR an attended/completed appointment; revenue sums each student's counselling_amount once (recorded amount, not a payment ledger). All-India total sums displayed active branches. Caller assigned leads use current assignment; calls use logged_by; invites/attended use distinct students per created_by, so invite rate can exceed 100% after reassignment. Show-up uses attended invitations, not visit-form completion without a caller-created meeting. Include inactive callers with history and label them inactive. New/upgrade badges count students with corresponding choice/letter document slots. In Counselling means a student_counselling row exists and allotted_phase is null.

Import definitions — Blank rows ignored, spreadsheet row numbers retained. Required header aliases resolve case-insensitively; ambiguous duplicate mapped headers rejected. Invalid optional parent phones reject that row rather than silently discard a contact. First valid occurrence wins; later repeated student phones are skipped. Existing global student phones yield only a generic duplicate reason, never branch/name details. Parent warnings cover same-branch existing contacts and accepted rows in the import. Round-robin starts at the first selected counsellor for each import and advances only on successful inserts. Empty selected subset is an error, not unassigned fallback. File contents are never stored. CSV exports quote values and neutralize formula-leading text. Ambiguous network import failures tell staff to refresh/retry; unique phone protection prevents duplicate leads.
